# Hashroom 文件摘要小助手

一个单文件、零依赖的静态网页：把文件拖进来，在浏览器本地计算多种摘要，并与已有的校验值比对。文件不会上传到任何服务器，页面也不加载任何第三方脚本。

## 功能

- 支持 MD5、SHA-1、SHA-224/256/384/512、SHA-512/224、SHA-512/256、SHA3-224/256/384/512、RIPEMD-160 和 CRC32。
- 可一次选择多种算法，结果可单条或整体复制。
- 比对预期值：能识别 `SHA-256: …`、`sha256sum` 输出、BSD 风格 `SHA256 (file) = …`、带空格或冒号的十六进制、Base64 摘要（如 SRI 的 `sha256-…`，需带算法名），以及多行输入。
- 启动时用标准测试向量自检，不通过的算法会被自动停用。
- 亮色 / 深色模式（默认跟随系统）和六种主题色。

## 使用

直接用浏览器打开 `index.html`，或用任意静态服务器托管。例如：

```sh
python3 -m http.server 8080
```

Web Crypto 在非安全上下文（非 HTTPS、非 localhost）下不可用，此时会自动回退到内置的纯 JS 实现，复制按钮也会回退到 `execCommand`。

## 实现说明

- SHA-1、SHA-256、SHA-384、SHA-512 在文件不超过 256 MiB 时使用 Web Crypto；其余算法使用内置的纯 JS 实现，边读边算。
- 文件整体读入内存失败时（如内存不足）会自动改为分块流式处理。
- 浏览器的 `Blob` 没有 `arrayBuffer()` 时（如 Safari 14 之前）改用 `FileReader` 读取。
- 超过 256 MiB 的文件完全按 1 MiB 分块流式处理，内存占用不随文件大小增长；读取下一块和计算当前块同时进行。
- SHA-3 的 Keccak-f 置换完全展开成局部变量运算，纯 JS 下的吞吐比逐 lane 循环写法高数倍。
- 页面带有严格的内容安全策略（CSP）：不允许任何网络请求，也不加载外部资源。
- 一次只处理一个文件；拖入多个文件时取第一个，拖入文件夹会提示不支持。
- 计算完成后，状态栏会显示本次计算的用时。
- 计算过程中关闭或刷新页面会先弹出浏览器的确认提示。
- 计算过程中按钮会变成“取消计算”；改动文件或算法同样会取消当前任务。
- 算法名对应的长度与读到的哈希不符时（如文件名 `sha256-notes.txt`，或标签写错），该名字会被忽略，改按哈希长度判断。
- 标着不支持的算法（如 BLAKE2、BLAKE3、SM3、MD4、CRC32C）的行不会按长度去猜、与等长的 SHA-256 等硬比，而是忽略并给出提示。
- 预期值的长度不是任何支持的摘要长度时（常见于复制不完整），会提示实际识别到的十六进制位数。
- 也能识别全角冒号、逗号分隔的哈希，以及 `--sha256 …` 这样的命令行写法。
- 算法名里的连字符也可以写成下划线（如 Python `hashlib` 的 `sha3_256`、`sha512_256`），并能识别 FreeBSD 的 `SHA512t256`。
- 粘贴整份 `sha256sum` / BSD 风格的校验清单时，只要有一行写明了当前文件的名字，带有其他文件名的行就不参与比对，并会提示忽略了几条。
- 超过 2048 个字符的行会被当作无法识别，每行最多只看前 8 个算法名，避免误粘贴大段文本时输入框卡顿。
- 比对预期值时，文件名里的算法名（如 `sha256.txt`）不会被当成算法标记；无法识别的行会被忽略并提示行数。
- 预期值里的不换行空格、全角空格等按普通空格处理，零宽字符会被忽略；清单里的文件名和当前文件名都先做 Unicode NFC 规范化再比较（macOS 上的文件名常是 NFD 形式）。
- coreutils 为含反斜杠或换行的文件名转义过的行（行首带反斜杠）同样能识别哈希和算法，只是不参与按文件名筛选。
- 同一个结果只要被任意一条预期值命中就算一致：文件被浏览器改名（如 `file (1).iso`）、清单里找不到它的名字时，其他文件的行不会让比对报“不一致”，横幅、状态栏和每行的标记始终一致。
- 挤满短十六进制片段的行也能很快解析完，输入框不会卡顿。
- 分组书写的哈希用多个空白分隔、或分隔符两侧带空格（如 `e3b0c442 - 98fc1c14 - …`）时也能拼回完整哈希，不会把第一组误认成 CRC32。
- 校验清单里哈希与文件名只用一个空格或制表符分隔时（脚本输出、表格粘贴），也能认出文件名并按文件筛选。
- CRC32 使用 slicing-by-8 查表，每轮处理 8 个字节，比逐字节查表快约一倍。
- 离开页面的确认只在计算期间注册，平时不影响浏览器的往返缓存（bfcache）。
- 不依赖正则后行断言和 `Element.replaceChildren()`，旧版 Safari 等浏览器也能正常加载页面。
- 算法勾号不画在 `input` 的伪元素上（各浏览器对表单控件上的伪元素支持不一致，Firefox 就不可靠），改画在相邻的 `span` 上。

## 验证

```sh
npm test    # 等价于 node tests/verify.js
```

脚本会从 `index.html` 中提取摘要实现，与 Node 内置 `crypto` 对比不同长度、不同分块方式下的结果，核对启动自检所用的标准向量，并测试预期值解析逻辑。CRC32 的对比需要 Node 22 及以上（`zlib.crc32`）。
