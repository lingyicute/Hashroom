# Hashroom 文件摘要小助手

一个单文件、零依赖的静态网页：把文件拖进来，在浏览器本地计算多种摘要，并与已有的校验值比对。文件不会上传到任何服务器，页面也不加载任何第三方脚本。

## 功能

- 支持 MD5、SHA-1、SHA-224/256/384/512、SHA-512/224、SHA-512/256、SHA3-224/256/384/512、RIPEMD-160 和 CRC32。
- 可一次选择多种算法，结果可单条或整体复制。
- 比对预期值：能识别 `SHA-256: …`、`sha256sum` 输出、BSD 风格 `SHA256 (file) = …`、带空格或冒号的十六进制、Base64 摘要（如 SRI 的 `sha256-…`，需带算法名），以及多行输入和同一行用空格分隔的 SRI 摘要（比对摘要本身，不模拟浏览器的 SRI 算法优先级）。
- 启动时用标准测试向量自检，不通过的算法会被自动停用。
- 亮色 / 深色模式（默认跟随系统）和六种主题色。

## 使用

直接用浏览器打开 `index.html`，或用任意静态服务器托管。例如：

```sh
python3 -m http.server 8080
```

Web Crypto 在非安全上下文（非 HTTPS、非 localhost）下不可用，此时会自动回退到内置的纯 JS 实现，复制按钮也会回退到 `execCommand`。

## 实现说明

- SHA-1、SHA-256、SHA-384、SHA-512 在文件不超过 256 MiB 时使用 Web Crypto；其余算法使用内置的纯 JS 实现，边读边算。
- 文件整体读入内存失败时（如内存不足）会自动改为分块流式处理。
- 浏览器用可中止的 `FileReader` 读取文件，不依赖 `Blob.arrayBuffer()`。
- 超过 256 MiB 的文件完全按 1 MiB 分块流式处理，内存占用不随文件大小增长；读取下一块和计算当前块同时进行。
- SHA-3 的 Keccak-f 置换完全展开成局部变量运算，纯 JS 下的吞吐比逐 lane 循环写法高数倍。
- 内容安全策略（CSP）禁止页面发起网络连接或加载外部资源，并只准许散列值匹配的两个内联脚本。
- 一次只处理一个文件；拖入多个文件时取第一个，拖入文件夹会提示不支持。
- 计算完成后，状态栏会显示本次计算的用时。
- 计算过程中关闭或刷新页面会先弹出浏览器的确认提示。
- 计算过程中可取消，改动文件或算法也会中止读取并丢弃旧结果。Web Crypto 无法打断，旧的原生任务尚未结束时，新任务改为分块计算，不重复整文件读取。
- 有算法标签时，摘要必须符合标注算法的长度与编码；例如截短的 SHA-256 不会被当作 SHA-224。没有标签时才按完整摘要的长度推断。
- 标着不支持的算法（如 BLAKE2、BLAKE3、SM3、MD4、CRC32C）的行不会按长度去猜；POSIX `cksum` 的十进制校验和也不是这里的 CRC32。混有无效或不支持的行时，明确提示只完成了部分比对。
- 预期值的长度不是任何支持的摘要长度时（常见于复制不完整），会提示实际识别到的十六进制位数。
- 也能识别全角冒号、逗号分隔的哈希，以及 `--sha256 …` 这样的命令行写法。
- 算法名里的连字符也可以写成下划线（如 Python `hashlib` 的 `sha3_256`、`sha512_256`），并能识别 FreeBSD 的 `SHA512t256`。
- 校验清单注明文件名时，只用当前文件对应的条目和未注明文件名的摘要。也支持常见的英文 CertUtil 两行输出和 PowerShell `Get-FileHash` 的数据行。
- 粘贴总量超过 256 Ki 个 UTF-16 码元时整份不解析；超过 2048 个码元的行不比对。以 `#`、`;` 或 `//` 开头的注释行忽略。
- 比对预期值时，文件名里的算法名（如 `sha256.txt`）不会被当成算法标记；无法识别的行会被忽略并提示行数。
- 摘要里的不换行空格、全角空格等按普通空格处理，零宽字符会被忽略，但文件名保留这些字符及首尾空格。没有精确匹配时才尝试 Unicode NFC（兼容 macOS 上的 NFD 文件名）。
- 支持 coreutils 行首反斜杠标记和文件名中的 `\\`、`\n`、`\r` 转义。
- 清单找不到当前文件，或者不同路径含同一个文件名时，不拿这些条目比对。文件被重命名后，可在确认原条目后只粘贴摘要。
- 无算法标签的摘要在任一候选算法命中后即匹配；没有命中、仍有同长度候选未算时，不提前报不一致。清单对同一文件、同一标注算法给出不同摘要时会报告冲突。未注明文件名的同算法（或同长度）摘要可以作为备选。
- “一致”只表示摘要相同，不认证文件的来源；应从可信渠道取得预期值，优先使用 SHA-256 等密码学摘要。
- 分组书写的哈希用多个空白分隔、或分隔符两侧带空格（如 `e3b0c442 - 98fc1c14 - …`）时也能拼回完整哈希，不会把第一组误认成 CRC32。
- 校验清单里哈希与文件名只用一个空格或制表符分隔时（脚本输出、表格粘贴），也能认出文件名并按文件筛选。
- CRC32 使用 slicing-by-8 查表，每轮处理 8 个字节，比逐字节查表快约一倍。
- 离开页面的确认只在计算期间注册，平时不影响浏览器的往返缓存（bfcache）。
- 不依赖正则后行断言和 `Element.replaceChildren()`，旧版 Safari 等浏览器也能正常加载页面。
- 算法勾号不画在 `input` 的伪元素上（各浏览器对表单控件上的伪元素支持不一致，Firefox 就不可靠），改画在相邻的 `span` 上。

## 验证

```sh
npm test    # 等价于 node tests/verify.js
```

脚本用可复现的数据对照 Node 内置 `crypto`，验证全部算法、分块方式和跨 512 MiB 的流式边界，也检查自检向量、取消读取、预期值解析与判定。CRC32 优先用 Node 的 `zlib.crc32` 对照；没有该接口时用独立的逐位参考实现。

修改 `index.html` 中的脚本后，先运行 `node tests/check-csp.js --write` 更新 CSP 白名单；`npm test` 会检查其是否与脚本一致。

浏览器交互回归可选用 Playwright；以下命令不改变项目依赖：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/browser.js
```

安装相应浏览器后，可用 `HASHROOM_BROWSER=firefox` 或 `HASHROOM_BROWSER=webkit` 运行同一套测试。脚本会临时启动回环 HTTP 服务，并验证直接打开本地文件的路径。
